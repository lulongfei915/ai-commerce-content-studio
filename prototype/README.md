# 造物 Studio｜可交互原型

原生 HTML、CSS、JavaScript 本地演示，用于需求核对与交互评审。正式产品将使用 React + TypeScript + React Flow；目标架构见[技术架构设计](../docs/技术架构设计.md)，项目范围见[项目总入口](../README.md)。

## 查看原型

在项目根目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory prototype
```

打开 <http://127.0.0.1:4173>。也可直接打开 [index.html](index.html)，涉及上传、本机保存和 ZIP 下载时建议使用 HTTP。日常体验无需安装前端依赖。

任务、节点草稿、新增商品与审核决定保存在当前浏览器。新增商品实拍压缩后本机保存；创作区临时补充图刷新后需重新上传。切换浏览器或访问地址可能使用不同记录。“使用指南 → 清除演示修改”恢复初始数据。

## 建议体验顺序

1. 点击“新建制作”，选择或添加商品，再选择主图、详情或视频；名称自动生成且可修改。已有任务从“全部任务”或当前任务菜单继续。
2. 选择“生成 / 画布 / 批量制作”。生成适合单个需求；画布组织节点与参考；批量配置多个独立生成项，图片和视频分开提交。
3. 编辑唯一的提交提示词，核对商品事实、参考、模型、规格和数量。三个入口都支持案例搜索、品类/媒体筛选与预览，筛选不清除已选参考。批量公共设置只影响继承字段，保留单项覆盖与已提交快照。
4. 视频用途区分片段与带货成片；片段无需完整分镜且不计成片交付，带货成片须确认分镜，相关输入变化后重新确认。
5. 生成保存后进行模拟 AI 初检；未通过自动拦截，通过后进入人工终审，异常可重试初检。人工对照实拍批准或填写原因驳回，返工保留父版本并重新初检。
6. 批准后明确采用，在“资产与交付 → 本次交付”按 SKU、模块、数量与规格补齐。各位置独立采用，同版本不可重复占位；导出前核对版本和缺口。
7. 在“公司管理”体验模板草稿、发布、停用和版本；在“公司素材”检索并引用同 SKU 已批准资产；侧栏头像切换演示身份，成员页体验权限调整与停用交接。

审核、交付页保留任务上下文，可返回创作。切换任务保留独立草稿；批量失败按输出或保存步骤恢复，成功结果保留。详细界面规则集中在[页面原型与交互说明](../docs/需求/02-页面原型与交互说明.md)。

## 模拟边界

- 生成、提示词优化、参考解析和 AI 初检使用预设本地演示，不分析实际媒体；初始“已确认/已批准”等状态是示例数据。
- 视频使用静态关键帧与分镜说明；ZIP 下载真实，但内容为示例图片、分镜 TXT、版本及缺口清单。
- 浏览器本机保存、角色切换、模拟并发不代表公司存储、服务端鉴权或后台执行已实现；关页时不运行后台服务。
- 正式产品的画布以 [LibTV 六张截图及设计基准](../docs/LibTV/画布设计基准.md)为主，HTML 原型用于核对工作区外壳及任务导航。

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面与资源加载入口 |

## 运行现有回归

回归脚本需要 Node.js、可解析的 `playwright` 包和 Chrome（默认 channel 为 `chrome`）。这些不是日常打开原型的依赖；当前目录未提供依赖清单或锁文件。先启动上面的 HTTP 服务，再从项目根目录运行：

```bash
STUDIO_TEST_URL=http://127.0.0.1:4173 node prototype/scripts/verify-consistency.cjs
```

其他浏览器 channel 可通过 `STUDIO_BROWSER_CHANNEL` 指定。脚本会覆盖 `output/consistency/` 的对应结果与截图；运行前如需追溯，应先保留旧输出。留存结果不表示本次整理重新执行了浏览器业务回归。

旧版操作说明与日期记录集中到[原型历史](../docs/历史/原型使用与迭代记录.md)，其中已被替代的行为不作为当前开发要求。
