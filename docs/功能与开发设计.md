# 造物 Studio｜功能与开发详细设计

> v1.0 · 2026-11-20 · 设计稿，待架构评审、供应商接入及真实负载验证；不代表功能已实现。依据 [PRD v4.6](需求/01-产品需求文档-PRD.md)、[页面与交互](需求/02-页面原型与交互说明.md)、[技术架构 v1.1](技术架构设计.md)、[LibTV 画布基准](LibTV/画布设计基准.md)、[模型使用指南](模型使用指南/Seedream-5.5-模型使用指南.md)及现有原型。业务冲突以 PRD 为准并同步文档；页面按交互说明和已确认的画布基准，技术遵循架构。原型的本地模拟不作为正式实现或验收证据。

## 1. 范围、阶段与设计约定

第一阶段覆盖 F01～F14、F16～F18，三个入口共用商品、生成、审核、资产及交付服务。实施顺序为单 SKU 主图闭环 → 详情与批量图片 → 片段及带货成片；完整第一阶段仍须通过 PRD 全部适用验收。F15 Agent 为第二阶段，首期只保留应用服务边界，不实现 Agent、技能市场或通用工作流。画布借鉴 LibTV 的节点、上下文操作和浮层，不引入导演台、独立音频、像素编辑、完整剪辑及专业资源库。区域/时间标注属于第一阶段正式要求，但不承诺精准局部重做。

**通用规则：**服务端从会话确定租户与角色；所有对象、关联和文件访问校验租户。业务对象使用稳定 ID 和 `version` 乐观锁；文件与发布版本不可变。列表分页、筛选由服务端执行，状态以服务端为准。每项下文的“验证”均为待执行的正式测试，AC 编号对应 PRD 第 7 节，不能用原型模拟代替。

推荐表以 `tenant_id` 为查询前缀建立组合索引：商品 `(tenant_id, sku)` 唯一；任务关联 `(tenant_id, task_id, sku_id)` 唯一；画布节点 `(tenant_id, task_id, node_id)` 唯一；引用按 `(tenant_id, target_id, sort_order)` 查询；执行/输出按任务、状态和时间索引；供应商请求键、步骤业务键及幂等键分别设唯一约束。采用唯一性在事务中锁位置和资产，并以包含任务、SKU、文件版本的唯一键兜底；删除采用记录时释放唯一键。跨租户关联由统一访问层、关联校验和适当复合外键共同保证。实际 DDL 与索引依据查询计划及迁移评审确定。

### 2.1 状态与事务边界

- 输出主流程：`queued → generating → saving → checking → pending_review → approved/rejected`；生成失败、保存失败、检查失败分别为 `generation_failed`、`save_failed`、`check_error`；检查不通过为 `blocked`。初检不足或无法判断进入异常/拦截，不能默认通过。重试只恢复失败步骤；返工创建新输出和资产版本，重新初检与终审。
- `needs_review`、授权失效、来源失效是独立阻塞标记，不覆盖既有审核结论；阻断新调用、终审、引用和下载。解除必须记录依据，不产生批准。批准、采用、交付分别为独立动作；片段不占成片位置。
- 提交在同一数据库短事务内校验权限、草稿版本、资料、引用、模型能力、分镜、交付预留与预算；写入输入快照、输出、预留、待执行步骤及幂等结果，提交后异步派发。数据库事务不包住供应商网络调用和对象存储。并发采用、审核、补缺、额度申请通过行锁、版本检查及唯一约束防重。
- 交付位置预留与候选输出数量分开计算。图片位置在首个合法执行被受理时建立一条预留，同一位置的多个候选不增加位置数；带货成片在分镜确认时建立预留，确认后再允许提交视频。重试复用原预留，未发出前取消可释放；生成失败在允许返工期间保留预留，明确终止该计划且无在途步骤后才释放。补缺先锁定位置，发现有效预留、在途执行或已采用版本时拒绝重复受理。只有采用版本计入已配齐。
- 草稿、布局、视口各有独立版本和保存状态。发生版本冲突返回当前版本和冲突对象，保留本地草稿供用户核对；不能静默覆盖。切租户/任务前处理未保存修改，取消旧查询；异步响应以租户、任务、对象及请求版本定位，不写入当前被选中的其他对象。

## 3. API 与文件契约

以下为实施契约草案，正式以 OpenAPI 及生成的前端类型为唯一机器可读契约。根路径 `/api/v1`；Cookie 会话与 CSRF 保护写请求，后端不信任客户端 tenant_id。JSON 字段用 `snake_case`；成功资源返回 ID、`version` 和状态；列表返回 `items`、`next_cursor`。时间使用 UTC ISO 8601，UI 按用户时区显示。修改请求携带 `expected_version`；冲突返回 409。付费或产生独立结果的提交带 `Idempotency-Key`，以租户、操作和键唯一保存请求摘要及结果；同键不同内容返回 409，同键同内容返回原结果。

统一错误格式：`{"code":"REFERENCE_INVALID","message":"参考素材已失效","field":"references[0]","details":{"reference_id":"…"},"request_id":"…"}`。校验 422，未登录 401，无权限 403，不存在或不可见 404，版本/状态冲突 409，额度不足或能力不可用使用稳定业务码并返回可定位对象；不返回供应商密钥或内部堆栈。

| 功能 | 主要接口（路径省略 `/api/v1`） | 关键输入 / 响应及权限 |
| --- | --- | --- |
| 会话、成员 | `POST /sessions`、`DELETE /sessions/current`、`GET /me`；`GET /members`、`PATCH /members/{id}`、`POST /members/{id}/handover` | 管理员变更角色/停用时传接手人及版本；验证最后管理员、本人及有效接手人；审计 |

| 文件 | `POST /files/uploads`、`POST /files/{id}/complete`、`GET /files/{id}/content` | 服务端发起并核验上传、真实类型及大小，完成后创建私有文件版本；读取和续传每次重新鉴权及校验有效性。调用火山方舟时由存储适配器生成短时签名 URL，过期后重新签发，不把对象改为永久公开 |

| 创作和引用 | `POST /tasks/{id}/creations`、`GET/PATCH /creations/{id}`、`POST /creations/{id}/references`、`PATCH/DELETE /creations/{id}/references/{ref_id}` | 草稿含 SKU、用途、媒体、提示词、参数、模板版本；引用传来源版本和用途，服务端校验并返回引用及新版本 |

| 批量及分镜 | `GET/PUT /tasks/{id}/batches/{media}`、`POST /batches/{id}/items`、`PATCH/DELETE /batch-items/{id}`；`PUT /creations/{id}/storyboard`、`POST /creations/{id}/storyboard/confirm` | 记录公共值及每字段继承/覆盖；确认检查镜头、事实和总时长，并返回绑定摘要 |
| 提交与恢复 | `POST /creations/{id}/executions`、`POST /batches/{id}/executions`、`GET /executions/{id}`、`POST /outputs/{id}/retry`、`POST /executions/{id}/cancel` | 提交传期望版本和范围，返回执行/输出 ID；批量全校验后原子受理；重试由服务端按失败步骤决定；取消只保证未发出部分 |
| 辅助 | `GET /prompt-cards`、`POST /creations/{id}/assistances`、`GET /assistances/{id}`、`POST /assistances/{id}/apply` | 类型为优化/图解析/视频解析；记录源版本、输入摘要、覆盖、费用和采用；应用时检查草稿版本，过期只保留建议 |
| 初检、审核、返工 | `GET /reviews`、`GET /assets/{id}/quality`、`POST /assets/{id}/precheck/retry`、`POST /assets/{id}/review`、`POST /assets/{id}/rework` | 决定含版本、批准/驳回、原因及区域/时间标注；驳回必填；返工绑定父版本及意见 |
| 资产与交付 | `GET /assets`、`GET /assets/{id}`、`PUT /delivery-positions/{id}/adoption`、`POST /tasks/{id}/delivery-packages`、`GET /delivery-packages/{id}/download` | 筛选 SKU/品类/场景/媒体/任务/状态；采用校验匹配和唯一性；打包请求含清单版本、完整/部分模式，下载重新校验 |
| 运维授权 | 管理端维护合同/许可证、模型额度、预算与供应商账户；查询调用、未知状态及审计 | 平台运营与客户管理员分权；敏感操作审计；费用授权产品交互尚待确认，不添加原型费用弹窗 |

**上传安全与交付：**文件使用服务端生成的对象键，检查媒体类型、大小、时长和解码，限制处理资源；私有存储通过授权代理或受控传输，不能依赖永久公开链接。打包建立时、生成完成时和每次下载/续传均核对权限、采用、来源有效性及清单版本；失效则明确失败并重新核对，不能静默省略。资源跨存储失败保留可恢复记录。

## 5. 画布详细设计（F03/F04/F05/F07/F12）

### 5.1 交互布局及节点

沿用 LibTV 的低干扰点阵、紧凑节点、选中上下文工具栏和画布内生成浮层。顶部为任务、SKU/全部、保存状态、审核和交付；底部为添加、选择/移动、整理、帮助及缩放/适应全部。空白态、添加菜单及双击空白提供商品素材、图片生成、视频生成，并允许取案例、公司素材、合规历史结果。画布以任务为单位，不新增多画布层级。

| 类型 | 节点数据与操作 | 业务约束 |
| --- | --- | --- |
| 商品实拍/案例/公司素材 | 展示缩略图、名称、来源、SKU/许可与版本；预览、来源、引用、可用时解析 | 实拍固定 SKU；案例范围须允许，成品须同 SKU 且有效批准 |
| 图片/视频生成 | 展示 SKU、用途、草稿和执行摘要；选中打开浮层，编辑参考、唯一提示词、模型及参数，核对并生成 | 媒体类型及模型能力校验；成片先确认分镜；节点不保存审核副本 |
| 结果 | 默认生成节点下方显示文件、版本、进度/初检/审核/复核状态；预览或播放、查看结果、审核、返工、允许时下载/引用 | 输出独立审核；新版本不自动替换已选来源，也不级联重跑 |

浮层锚定选中节点且限制在画布边界，空间不足调整位置；小屏改画布内部底部面板，长内容独立滚动，参数与提交可达。关闭/Escape 返回触发节点及焦点，视口不被意外重置。输入、选字和滚动区域使用 React Flow 的 `nodrag` / `nopan` / `nowheel` 等机制并处理焦点，编辑时删除等快捷键不作用于画布；覆盖面板限制焦点及背景操作。状态文字与可访问名称补足图标。选中时高亮直接上下游；可仅看选中关系并提示过滤，提供适应全部、回到选中和 SKU 定位。

### 5.2 React Flow 数据流和引用

- `CanvasPage` 获取任务布局及业务对象；`CanvasFlow` 使用受控 `nodes`/`edges`、稳定 `nodeTypes`/回调；节点只包含节点 ID、业务 ID 与展示所需字段，状态从 TanStack Query 按 ID 读取。Zustand 仅存选中、浮层、连接中的目标等临时状态；拖动位置暂存本地，结束或防抖保存布局。视口单独按用户保存；失败显示未保存并可重试，409 保留本地布局并要求核对。
- 业务输入引用是唯一事实：从来源点击“引用”再点击目标“输入”，或使用连接手柄；前端预检 SKU、类型、数量、许可、就绪与循环，提交引用接口并等待成功后投影连线。服务端再次检查目标及版本权限、引用用途、模型能力、依赖图环；删除/改用途同理。失败保留旧关系并定位错误。连线、参考缩略图、正文可选标签都指向稳定 `reference_id`；显示编号仅是排序，排序不改变真实绑定。删除引用后正文中的标签标为失效并阻止提交，不自动改写手写正文。
- 将实际引用版本、用途、顺序和媒体发送至供应商适配器，而非文件名代替媒体。对草稿引用变更使关联分镜确认失效；提交时重新验证来源及模型能力并冻结快照。结果按租户、任务、生成对象、执行/输出 ID 写回；V1 用作视频输入后，出现 V2 不改变 V1 引用。
- 删除节点先说明影响：移除布局节点时不得删除已提交输出或历史；若涉及当前草稿引用，先显式确认并通过引用 API 处理。整理仅更新布局，不执行生成、修改审核或引用。切换 SKU、选中、拖动、缩放、连线均不触发付费调用。

### 5.3 性能与验证

缩略图按需加载、视频点击后加载；节点组件 memo 化，缩放/拖动不刷新全部媒体或请求。以 1280×600 桌面和 390×844 手机为基准，在 50 个节点、100 条连线、20 个媒体缩略图的代表性数据下，平移/缩放/拖动的交互响应 p95 ≤100ms，连续操作期间帧率不低于 30fps，单次主线程长任务不超过 200ms；打开或关闭浮层不重置视口，媒体不阻塞画布操作。该门槛用于达到 LibTV 的使用感，LibTV 截图本身不作为性能证据。记录浏览器、设备、节点/边数量、文件尺寸、首屏、响应和内存。验证六类参考状态：空白、图片编辑、添加菜单、视频编辑、多参考视频、多资产图片；覆盖画布内长文本与短屏、连线/缩略图/标签同步、悬空标签、非法连接、保存失败/冲突、刷新恢复、任务切换及结果归属，另运行 AC-03～05、21、35、37。真实媒体和服务端记录是验收依据。

## 6. 后台执行与恢复细节

1. 接收：校验全部输入、授权、预算上界和分镜，在同一短事务冻结快照、预留额度/位置、写输出及待执行步骤。批量任何草稿不合法均不受理；重复幂等请求返回原执行。
2. 调度：按客户轮转和每批派发上限领取步骤；数据库租约/领取版本防旧 Worker 写回，Redis 消息丢失由扫描补发。供应商与客户在途并发和共享频率由数据库统一控制；不把本机 Worker 并发当作外部额度。
3. 调用：持久化调用意图与供应商可查询标识，再提交；如响应超时无法确定受理，进入 `unknown`，保留占用及费用预留，先用原请求查单，不能用新请求盲目重试。供应商必须具备有效幂等或可靠查单；无法核实交运营处理。
4. 后处理：结果可取回后只做归档及规格检查，保存失败重取原结果；初检异常只重检。每步幂等地保存记录，额度和预留仅在已核实终态释放/结算一次。取消未发出步骤释放相应预留；已发出按供应商真实状态继续查单和结算。
5. 下载：生成完整/部分包的任务依据固定清单构建，完整包必须无缺口；部分包列出缺口。打包后如引用、批准或权限失效，下载拒绝并要求重新核对。

## 7. 工程目录与代码规范

正式工程尚未创建；以下为目标目录，按领域与职责组织，避免单个全局组件或服务承载所有功能。原型独立保留，不迁入生产运行链。

```text
apps/
  web/
    src/
      app/                 # 路由、会话、Provider、错误边界
      shared/              # API 客户端、通用 UI、类型、工具
      features/
        auth/ products/ tasks/ templates/ cases/
        creation/ batch/ canvas/ storyboard/ prompt-assist/
        executions/ reviews/ assets/ delivery/ members/
      pages/               # 路由装配，不承载领域规则
    tests/                 # 集成与端到端；单元测试可邻近功能
    package.json
  server/
    app/
      api/                 # 路由、依赖注入、请求响应 schema
      modules/             # 每个领域各有 application/domain/infrastructure
        identity/ products/ standards/ production/ canvas/
        execution/ quality/ assets/ delivery/ commerce/
      shared/              # 配置、数据库、租户上下文、日志、错误
      adapters/            # 模型、对象存储、媒体工具等外部适配
      entrypoints/         # API、scheduler、Celery worker
    migrations/            # Alembic
    tests/                 # 单元、集成、契约与故障恢复
    pyproject.toml
 deploy/                    # Docker、Compose、Nginx、安装升级与恢复
```

依赖方向：页面→feature→shared；跨 feature 通过公开接口或应用层组合，不直接访问其他 feature 内部状态。后端 API/Worker→应用服务→领域规则/仓储接口→基础设施实现；领域层不依赖 FastAPI、ORM 或供应商 SDK，外部调用不放数据库事务内。每个模块拥有写入规则，共用对象通过应用服务访问。

- TypeScript 开启 strict，禁止无理由 `any`；组件按视图、状态 hook、API 和类型拆分，表单/服务端数据各有唯一来源。Python 加类型标注、Pydantic 输入校验，SQLAlchemy 会话按请求/步骤管理；迁移入库并在升级测试中验证。前端类型由 OpenAPI 生成，禁止手写第二份接口契约。
- 常规源文件建议 ≤300 行，软上限 400 行；超过须按职责拆分或在代码评审说明原因。组件/函数优先单一职责，建议函数 ≤50 行；生成代码、迁移、测试数据例外。行数不以机械拆文件代替合理抽象。单文件绝对上限由 CI 对非豁免源码设为 500 行，历史超限需先列基线和整改，不直接阻断既有原型。
- 格式/质量：前端 ESLint、Prettier、TypeScript 类型检查，后端 Ruff、类型检查、pytest；依赖锁文件与安全扫描，密钥仅在环境/密钥服务中保存。PR 必须提供需求/AC、变更、验证、迁移/回滚影响；CI 运行格式、静态检查、针对性单元/集成、构建和迁移检查。生产日志带 request_id、tenant_id、task_id、execution_id，脱敏不记录完整媒体或密钥。
- 自动测试重点为业务规则和风险：跨租户与角色、状态转换、版本冲突、引用与分镜、幂等与并发、真实媒体规格、恢复和下载撤回；端到端覆盖三入口关键路径和键盘/小屏。供应商沙箱及受控真实预算测试另保留请求、输出、费用与审核证据。
