> 2026-11-21：正式工程骨架已建立在 `apps/web`、`apps/server` 和 `deploy`，健康接口、迁移入口、CI、OpenAPI 类型生成和基础质量检查已接通。业务模块与真实生成链路仍按开发实施清单推进。

## 查看原型

在项目根目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory prototype
```

打开 <http://127.0.0.1:4173>。原型无需安装前端依赖，也可直接打开 `prototype/index.html`；上传、本机保存及 ZIP 下载建议使用 HTTP。

任务、草稿、审核决定和新增商品保存在当前浏览器。保持相同浏览器和访问地址可继续使用本机记录；文件打开方式或访问地址变化会影响记录可见性。“使用指南 → 清除演示修改”可恢复初始数据。详细操作和模拟边界见[原型说明](prototype/README.md)。

## 文档与实现的依据

- **业务规则、状态和正式验收**：以 PRD 第 4、7 节及 AC 编号为准。
- **页面与交互**：以页面原型与交互说明为准，并满足 PRD；画布后续调整结合 LibTV 设计基准。当前原型尚未按该基准完成重排。
- **技术与工程边界**：以技术架构设计为准；功能与开发设计补充具体接口、数据结构、状态机和开发任务。
- **业务证据与追踪**：真实案例说明背景，案例对照追踪覆盖；不将设计覆盖等同于真实服务已实现。
- **验证证据**：区分留存测试输出、本次实际检查和历史叙述；原型检查不能替代正式服务验收。README 和历史说明不覆盖上述业务规则。

首个需求依据来自 CASE-021 鞋服电商案例，需求与成交已确认，未公开独立量化 ROI；跨品类适用性仍须实测。

## 当前范围与状态

“生成 / 画布 / 批量制作”三个入口共用商品、任务、审核和交付。流程为：选择商品与制作内容 → 编辑提示词与参数 → 提交生成 → AI 初检 → 人工终审 → 明确采用 → 按 SKU 核对交付。

| 当前可体验的本地演示 | 正式开发仍需完成 |
| --- | --- |
| 商品与任务管理、三种入口、提示词与参考编辑 | 公司商品库、真实媒体解析及生成服务 |
| 批量公共/单项配置、模拟排队、逐输出恢复 | 后台执行、供应商查单、关页接续、并发与成本控制 |
| 片段/带货成片用途、可编辑分镜与确认 | 真实视频生成、播放与镜头语义验证 |
| 模板草稿/发布/版本、公司资产、角色与成员交接 | 真实账号、公司存储、服务端鉴权与审计 |
| 模拟初检、拦截、终审、返工、采用与 ZIP 下载 | 真实一致性检查、正式文件交付及可追溯记录 |

初检通过不等于人工批准，批准不自动采用；同一版本不能重复占用多个交付位置。片段不计入带货成片交付，带货成片须确认分镜。示例 ZIP 可真实下载，但图片为示例排版、视频为分镜 TXT，不含真实生成成片。当前界面不展示价格、费用勾选或费用确认。

第一阶段先接通单 SKU 主图的完整生产链路，再扩展详情、批量图片和带货视频。第二阶段引入 Agent 辅助理解、推荐、规划与协调，仍保留人工终审。不扩展 ERP、自动发布、完整详情页搭建、完整剪辑器、通用工作流编辑器或技能市场。

## 开始正式开发

正式技术选型：React + TypeScript + React Flow（`@xyflow/react`），配套 Vite、pnpm、React Router、TanStack Query、Zustand、Ant Design；后端为 Python/FastAPI、MySQL 8.4 LTS、Celery/Redis 和私有对象存储，采用 Nginx/HTTPS + Docker 部署。

1. 对照 PRD、页面交互与画布基准核对首期范围，完成架构评审及关键验证。
2. 评审[功能与开发设计](docs/功能与开发设计.md)中的共用对象、接口契约、状态转换、异常恢复及开发验收任务。
3. 按架构建立正式工程：`apps/web/` 放 React 前端，`apps/server/` 放后端及 API/调度器/Worker，`deploy/` 放部署资料。这些目录将在实际开发时创建。
4. 优先完成单 SKU 的真实生成、初检、终审、采用和交付闭环，再按 PRD 验收标准逐步扩展。
